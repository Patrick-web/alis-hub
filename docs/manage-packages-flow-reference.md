# Alis Extension Manage Packages Flow Reference

Source: `~/.vscode/extensions/alisexchange.alis-build-2.0.398/dist/extension.js`
Command: `alis.workspace.manage-packages` — handler function `Wmt()`
Menu label: "Manage Packages (install/upgrade/add)"
Category: "alis • Workspace"

---

## Flow Sequence

### 1. Product Validation
- Reads active product from workspace context via `Ge().getProduct()`
- If no product selected: aborts with "Packages • Aborted, no product selected for the workspace"
- Extracts `orgId` and `defId` from product path: `definitions/{orgId}.{defId}`

### 2. Fetch Organisation (API call)
- **Service:** `alis.os.products.v1.OrganisationsService`
- **Method:** `GetOrganisation`
- **Request:** `{ name: "organisations/{orgId}", readMask: { paths: ["name", "packages_domain"] } }`
- **Response field used:** `packages_domain` — the registry domain for this org (e.g., "npm", "pypi", "pub.dev", "pkg.go")
- Error if fails: "Packages • Aborted, unable to retrieve the packages domain from the Organisation ({orgId})."

### 3. Action Picker (QuickPick)
Title: "Install or Upgrade packages"

| Label | Description | Value |
|---|---|---|
| Upgrade Defined | Only upgrade {packagesDomain} packages generated by your Define steps | `upgrade_defined` |
| Upgrade All | Perform an upgrade for all the specified packages | `upgrade` |
| Install | Install all relevant packages | `install` |
| Add | Add your {packagesDomain} package | `add` |

- Abort if cancelled: "Packages • Aborted, no install or upgrade action has been selected."

### 4. Language File Discovery
Function: `Ec()` — scans workspace folders for language manifest files.

| Language | File | Enum |
|---|---|---|
| Go | `go.mod` | `Language.GO` |
| Node.js | `package.json` | `Language.NODE` |
| Python | `pyproject.toml` or `requirements.txt` | `Language.PYTHON` |
| Dart | `pubspec.yaml` | `Language.DART` |

- If multiple folders found: shows QuickPick titled **"Packages • Select Folder(s)"**
  - Placeholder: "Select the folders where the relevant language files reside"
  - `canPickMany: true`, all items pre-selected
  - Returns array of `{ folderPath, language, files[] }`
- If nothing found: "Packages • No language specific files (go.mod, package.json, etc.) were found."
- Abort if user clears all selections: "Packages • Aborted, no packages selected or found"

### 5. Python Virtual Environment Check (conditional)
Only triggered if Python projects are in the selection.

- Checks for `.venv` at `{productBuildPath}/.venv`
- If missing: shows modal — "Python virtual environment not found. Would you like to create a virtual environment?" with option ["Create"]
- If confirmed:
  1. `python3 -m venv .venv`
  2. `.venv/bin/python3 -m pip install keyring keyrings.google-artifactregistry-auth wheel`
  3. `gcloud auth application-default login`
  4. Updates VS Code workspace `python.defaultInterpreterPath` setting

### 6. Generate Package Scripts (API call)
Shows progress notification: "Packages • Preparing {action} scripts"
- Message 1: "Finding package scripts..."
- Message 2: "Preparing package registry access..."
- Message 3 (if Dart): "Preparing Dart package access..."

**Service:** `alis.os.vscode.v2.VscodeService`
**Method:** `GeneratePackageScripts`

**Request:**
```
GeneratePackageScriptsRequest {
  definition: "definitions/{orgId}.{defId}"
  locations: [
    GeneratePackageScriptsRequest.Location {
      language: Language enum (GO | NODE | PYTHON | DART)
      workingDirectory: "/abs/path/to/folder/with/manifest"
      buildDirectory: "/abs/path/to/product/build/dir"
    }
    // one entry per discovered language folder
  ]
  targetPlatform: Platform.WINDOWS  // only set on Windows
  excludeGcloudAuth: true
}
```

**Response:**
```
GeneratePackageScriptsResponse {
  goLangList: [ Scripts, ... ]
  nodeList:   [ Scripts, ... ]
  pythonList: [ Scripts, ... ]
  dartList:   [ Scripts, ... ]
}
```

Each `Scripts` object:
```
Scripts {
  title:            string          // human-readable label
  workingDirectory: string          // directory to cd into before running
  language:         Language enum
  installPackages:  StringValue     // shell command for "install"
  upgradePackages:  StringValue     // shell command for "upgrade"
  upgradeDefined:   StringValue     // shell command for "upgrade_defined"
  addDefined:       StringValue     // shell command for "add"
}
```

- Abort if response lists are all empty: "Packages • Aborted, no relelvant package scripts were found."

### 7. Package Registry Authentication
- Calls `GT(context, orgId, defId)` — sets up Google Artifact Registry auth for Go/Node/Python
- Calls `sre(context, orgId, defId)` — sets up Dart-specific registry auth (only if `dartList` non-empty)
- Both are implicit side-effects; no separate API call visible in flow

### 8. Execute Scripts in Terminal
For each `Scripts` entry across all language lists:

1. Open (or reuse) terminal named: `alis • packages • {relative/path/to/workingDirectory}`
2. Pick the script field based on selected action:
   - `install` → `installPackages.getValue()`
   - `upgrade` → `upgradePackages.getValue()`
   - `upgrade_defined` → `upgradeDefined.getValue()`
   - `add` → `addDefined.getValue()`
3. `terminal.sendText("cd {workingDirectory}", true)`
4. `terminal.sendText(scriptCommand, true)`
5. Small delay (2 s race + 250 ms) via `zmt()` before moving to next script

## Proto / gRPC Surface

### `alis.os.products.v1.OrganisationsService`
| Method | Request | Response |
|---|---|---|
| GetOrganisation | GetOrganisationRequest | Organisation |

Key fields:
- `GetOrganisationRequest.name` = `"organisations/{orgId}"`
- `GetOrganisationRequest.readMask.paths` = `["name", "packages_domain"]`
- `Organisation.packages_domain` — string registry domain

### `alis.os.vscode.v2.VscodeService`
| Method | Request | Response |
|---|---|---|
| GeneratePackageScripts | GeneratePackageScriptsRequest | GeneratePackageScriptsResponse |

Streaming: none — all calls are unary.

## Data Needed at Each Step

| Step | Data | Source |
|---|---|---|
| 1 | Active product | Workspace context |
| 2 | `orgId`, `defId` | Parsed from product path |
| 2 | `packages_domain` | GetOrganisation API |
| 3 | Selected action | User QuickPick |
| 4 | Language folders + manifests | Local filesystem scan |
| 5 | Python `.venv` existence | Local filesystem |
| 6 | Script commands per language | GeneratePackageScripts API |
| 8 | Terminal output | Scripts run in VS Code terminals |

---

## Implementation Notes for alis-hub-v3

- The app already has `ScanNeuronPackages` (local file scan) which covers Step 4 data.
- Step 6 (`GeneratePackageScripts`) is the key new API call — it returns the exact shell commands to run, generated server-side based on the org's registry config.
- No streaming needed; run the returned commands in a shell and stream the output to the UI (same pattern as build logs).
- The "product build directory" (`buildDirectory`) is the same path used elsewhere: `~/alis.build/{org}/build/{product}/`.
- `packages_domain` from the org is purely cosmetic (used to label the action picker) — the server generates the correct commands regardless.
